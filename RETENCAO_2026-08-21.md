# Adendo 2 (21/08, noite) — Google Play Billing no Android

Motivo: o app da Play Store é um TWA que abria o checkout da Kiwify dentro do app. Além de
não segurar cartão (sem trial automático), isso fere a política da Play para assinaturas
digitais. Agora, DENTRO do app da Play, a compra passa pelo Google Play Billing; no site
puro, continua a Kiwify.

| Peça | Onde | O que faz |
|---|---|---|
| Compra no TWA | `page.tsx` (`isPlayTWA`, `comprarPlay`, `restaurarPlay`) | Detecta o app da Play (Digital Goods API + referrer `android-app://`). Botão "Começar 3 dias grátis" e "Assinar" chamam o Play Billing. Sem compra, sem acesso — igual ao iPhone. |
| Verificação | `app/api/play/verificar/route.ts` + `lib/play-billing.ts` | Confirma o `purchaseToken` na Google Play Developer API (conta de serviço), libera Premium até `expiryTime`+3 dias, grava em `compras_play` e faz o **acknowledge** (sem ele o Google estorna em 3 dias). |
| Renovações/cancelamentos | `app/api/play-webhook/route.ts` | Recebe as notificações em tempo real (Pub/Sub push), reconsulta a API e atualiza o Premium. |
| Tabela | `migracao_2026-08-21_play_billing.sql` | `compras_play` (token → conta). Rodar no Supabase. |

### B. Google Cloud — conta de serviço + notificações
1. console.cloud.google.com → projeto (pode criar "vonai-play") → **IAM → Contas de serviço → Criar** ("vonai-play-billing") → Chaves → **Criar chave JSON** (baixa um arquivo).

3. Cloud → **Pub/Sub → Tópicos → Criar** `vonai-play`. No tópico, **Permissões → Adicionar principal** `google-play-developer-notifications@system.gserviceaccount.com` com papel **Pub/Sub Publisher**.
4. No tópico → **Assinaturas → Criar**: tipo **Push**, endpoint `https://vonai.com.br/api/play-webhook?token=<PLAY_WEBHOOK_TOKEN>` (invente um token longo).
5. Play Console → app → **Monetização → Configuração de monetização → Notificações em tempo real** → nome do tópico `projects/<id-do-projeto>/topics/vonai-play` → Salvar → "Enviar mensagem de teste".
